REAL ESTATE FRONTEND — TWO VERSIONS
===================================

Choose one of two versions depending on what works during the lab.

VERSION A: WITHOUT MONGODB
--------------------------
Folder: without_mongodb
File: index.html

- AngularJS service stores records in a JavaScript array.
- Does not require Node.js, MongoDB, Compass, or a backend.
- Add, delete, filter, and sort work in the current browser session.
- Data resets when the page is refreshed.
- Use this version if MongoDB does not start or the question only asks for
  AngularJS frontend/service/filter/sort/CRUD.

Run:
1. Open `without_mongodb/index.html` in Chrome, or preferably serve it:
   Open CMD in `without_mongodb` and run:
       npx http-server -p 5501
   Then open http://127.0.0.1:5501
2. If prompted, allow npx to download http-server.
3. You do not need MongoDB.

VERSION B: CONNECTED TO MONGODB
-------------------------------
Folder: with_mongodb
- public/index.html: AngularJS frontend
- backend/server.js: Node/Express API and Mongoose model
- backend/package.json: dependencies
- backend/.env: database URL and port

Important: browser JavaScript should NOT connect directly to MongoDB. The
AngularJS service sends HTTP requests to the Node/Express backend. The backend
connects to MongoDB using Mongoose.

Steps:
1. Make sure Node.js is installed:
       node --version
       npm --version
2. Start MongoDB Community Server.
   On Windows press Win+R, type services.msc, find MongoDB and click Start.
   Compass is a GUI client; Compass alone does not run the database server.
3. Open CMD in `with_mongodb/backend` and run:
       npm install
       npm start
   Expected: Connected to MongoDB; Backend running at http://127.0.0.1:3000
4. Keep that terminal open.
5. Open another CMD in `with_mongodb/public` and run:
       npx http-server -p 5500
6. Open:
       http://127.0.0.1:5500
7. Add a record, then open MongoDB Compass and connect to:
       mongodb://127.0.0.1:27017
   Database `realestatedb` and collection `properties` appear after the first
   successful insert.

IF MONGODB FAILS DURING THE EXAM:
- Use VERSION A immediately. It does not depend on MongoDB.
- You can still demonstrate add/delete/filter/sort from the AngularJS frontend.
- Explain that Version A keeps data in memory, so it is not persistent.

WHAT "SERVICE CONNECTED TO MONGODB" MEANS
-----------------------------------------
The service in the connected frontend calls:
  GET    http://127.0.0.1:3000/api/properties
  POST   http://127.0.0.1:3000/api/properties
  DELETE http://127.0.0.1:3000/api/properties/:id

The backend uses Mongoose to connect to MongoDB. AngularJS does not connect
straight to the MongoDB server from the browser.

SERVICE VS FACTORY
------------------
Both provided versions use ONLY:
  app.service("PropertyService", ...)

No factory is included. If another template has both service and factory and
the question requests only service:
1. Delete the whole `app.factory("PropertyFactory", ...)` block.
2. Remove `PropertyFactory` from controller parameters.
3. Replace calls like `PropertyFactory.getAll()` with the matching
   `PropertyService` method.
4. Remove the factory script tag if the factory is in a separate file.
Do not delete the service.

FIELD CONVERSION TO LIBRARY MANAGEMENT
--------------------------------------
For a Library Management question, example fields:
  bookTitle, author, category, year

Frontend:
- Change form ng-models to newBook.bookTitle, newBook.author, etc.
- Change display expressions to book.bookTitle, book.author, book.category,
  book.year.
- Rename the list variable from property to book consistently.
- Change heading to Library Management System.
- In no-database version, change the service array objects and controller
  property names to books/book. The core array CRUD pattern remains the same.

Connected version:
- Change API URL from /api/properties to /api/books.
- Change backend Mongoose schema fields to bookTitle, author, category, year.
- Change the model from Property to Book.
- Change GET/POST/DELETE routes to /api/books and ensure POST reads the same
  req.body fields as the frontend sends.
- Change database name in .env if desired, for example librarydb.
- Update filters: type -> category; price range can be removed or changed to
  year range.
- Field names must match across ng-model, service payload, backend req.body,
  Mongoose schema, and ng-repeat display.

COMMON ERRORS
-------------
MongoNetworkError ECONNREFUSED 127.0.0.1:27017:
- MongoDB server is not running or not installed. Use services.msc.
- For the lab, switch to without_mongodb version if needed.

Cannot connect to backend:
- Ensure `npm start` is still running in backend terminal.
- Open http://127.0.0.1:3000; it should say API is running.
- Check the service URL and port match.

No data in Compass:
- Add a record first, then refresh Compass.
- Confirm the database URI and database name in .env.

Fields do not appear:
- Match the HTML ng-model, JavaScript object keys, backend req.body names,
  Mongoose schema fields, and display expressions exactly.

EXAM SUMMARY
------------
Without MongoDB = AngularJS service + in-memory array.
With MongoDB = AngularJS service ($http) + Node/Express API + Mongoose + MongoDB.
